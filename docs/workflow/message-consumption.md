# 消息接管（可选）

默认行为不变：没有「接管消息」节点的旧工作流不会阻止其他服务处理消息。

画布例子：开始 → 判断 message == awa → true → 发送 awa → 接管消息 → 结束。
建议放在发送节点后面：发送失败不接管，允许其他消费者兜底。也可以放在发送前，表示
无论后续发送是否成功，都由本工作流负责。条件的 false 分支不接管。
把发送节点的 `send_ok` 接到接管节点的「接管条件」端口，连空内容／无目标而跳过发送的
情况也不会接管。该端口不接线表示无条件接管；接线时 false / 0 / 空值表示不接管。

「结束」只结束工作流，「接管消息」才表示这条消息不应再交给后续消费者。
接管不停止本工作流剩余节点，也不阻止同归属的其他工作流运行。

## 独立 AI 服务的接入

NapCat 广播不会因为其中一条连接处理了消息，就撤销另一条连接的消息。
独立 AI 服务必须在调用模型前，调用 `POST /api/messages/dispatch`：

- Authorization: Bearer `<机器人 OneBot 凭证>`（不是控制台登录令牌）
- JSON: `self_id`, `message_id`, `user_id`, `chat`（group/private）, `chat_id`, `message`
- 所有 ID 是字符串；message 保持原始 OneBot raw_message，不能删除 @ 或引用。
- 成功响应 `data.consumed=true`：不调用 AI；false：照常处理。

归属从凭证得出，客户端不能指定 owner_id。凭证必须对应当前在线的机器人。
HTTP 与 WebSocket 按归属、平台、机器人、会话、消息 ID 共用一个执行回执：
先到的执行，后到的复用；重试不重复发消息。已完成回执保留五分钟（进程重启不保留）。
仍在运行的任务不因调用方超时而取消，也不会被回执容量清理掉。

25 秒内还无法决定时返回 504，表示工作流仍在运行：**不要当作 false 再调用 AI**。
可以告知用户工作流仍在处理；不要重新运行这条消息或取消已经生成的回复。
TickNeko 无法连接时，集成方可按自己的故障策略退回普通 AI。

这是协作协议，不是全局拦截开关：未接入这个接口的其他服务仍会收到 NapCat 广播。
